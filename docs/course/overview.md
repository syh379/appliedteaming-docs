# A team course: overview

**What it is**: the full team experience. Inside a pilot class, a student moves through a small number of **check-ins** across the semester, and everything they submit flows into three views and a growing set of keepsakes.

## The shape of a course

Every pilot course is the same handful of check-ins (**start, middle, end**), just with different names and lengths:

| Course | Check-ins |
| --- | --- |
| **Info 213** | Team Charter → Mid-point check-in → Retrospective *(3)* |
| **MEC ENG C178 / BIO ENG C137** | Start → Mid-point 1 → Mid-point 2 → End *(4)* |

Each check-in captures the **same three things**: an individual **goal**, a team **role**, and a few core **team attributes**. At the **start** the attributes are chosen aspirationally (what the team wants to get right); from the **mid-point** on, each gets a light 👍 / 👉 / 👎 on how it's *actually* going, with one short reflection. Same surveys everywhere; one course simply has an extra mid-point checkpoint.

## What a student moves through

<div class="steps">

1. **[Welcome & sharing stories](/course/welcome)**: a warm first step that turns a roster into a room of humans.
2. **[The dashboard](/course/dashboard)**: always shows progress, the next step, and what's still to unlock.
3. **[A check-in](/course/checkpoint)**: the short survey, done at each checkpoint.
4. The three views: **[Class](/course/class-view)**, **[Team](/course/team-view)**, **[Personal](/course/personal-view)**.
5. **[Artifacts](/course/artifacts)**: keepsakes that accumulate and unlock.
6. **[Finishing](/course/finishing)**: how completing the course feeds the student's profile map.

</div>

::: tip The one rule that shapes everything
The **class view updates live** the moment anyone submits. The **team report and the individual capstones wait for the whole team**, so no one's picture is partial, and the final report can include teammates' feedback. This is covered on each view's page.
:::
