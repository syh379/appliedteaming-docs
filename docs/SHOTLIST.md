# Screenshots, how they're captured

Screenshots are **generated by a reproducible script**, not captured by hand, so
they always match the live app. The scripts live in the **main app repo** at
`scripts/docs/` (they need the running app), and write retina PNGs (1440×900 @2×)
straight into this guide repo's `docs/public/screenshots/` via the `AT_OUT` env var.

## Regenerate everything

From the **app** repo (`appliedteaming/`), with the dev server running
(`npm run dev`) and `.env` present (needs `SUPABASE_SERVICE_ROLE_KEY` + the
Supabase URL). Point `AT_OUT` at this repo's screenshots folder:

```bash
export AT_OUT=../appliedteaming-docs/docs/public/screenshots   # adjust to your path

# 1. Seed the three sessions, password-free (magic link + the app's /auth/confirm)
node --env-file=.env scripts/docs/seed-session.mjs maya.demo@berkeley.edu                                    # → .auth/state.json
AT_STATE=.auth/done.json    node --env-file=.env scripts/docs/seed-session.mjs testuser2@appliedteaming.com # → .auth/done.json
AT_STATE=.auth/faculty.json node --env-file=.env scripts/docs/seed-session.mjs stef.demo@berkeley.edu         # → .auth/faculty.json

# 2. Capture
node scripts/docs/capture.mjs                                  # student (Maya) + completed-course (Jordan)
AT_STATE=.auth/faculty.json node scripts/docs/capture.mjs faculty
node --env-file=.env scripts/docs/capture-onboarding.mjs       # onboarding (spins up + deletes a throwaway account; uploads a tiny résumé)
```

Sessions are minted through the Supabase admin API (a magic-link token verified
server-side, no passwords). Re-running overwrites the PNGs in place, so a docs
refresh after a UI change is a couple of commands.
